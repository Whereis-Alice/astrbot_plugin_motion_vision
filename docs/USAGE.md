# 使用指南

Motion Vision 的目标不是把媒体简单转换成图片，而是把画面、声音和文字资料分开整理，再交给当前对话模型。这样模型能知道每条证据来自哪里，也能在某一层失败时继续使用其他层。

## 一条消息会发生什么

大致流程如下：

```text
消息与引用
  ├─ 动图 → 按时间抽帧
  ├─ 视频 → 按时长规划采样 → 抽帧
  ├─ 视频音轨 → 附带或转写
  ├─ B 站链接/卡片 → 元数据、字幕、专栏、视频文件
  └─ 分享卡片 → 提取受限字段
                    ↓
          统一预算、缓存与安全限制
                    ↓
             注入本轮模型请求
```

纯媒体消息没有文字提问时，插件会补充一个简短的默认问题，避免部分模型因为请求没有文本而忽略附件。

## 支持的来源

可以直接发送或引用：

- GIF、动态 WebP、APNG；
- 常见视频文件，例如 MP4、MOV、MKV、WebM、AVI、FLV、TS；
- AstrBot 能还原的附件、消息链、群文件和私聊文件；
- 远程视频地址；
- B 站 BV 号、av 号、完整链接、b23.tv 短链和分 P 链接；
- QQ / OneBot 的分享卡片、引用卡片和结构化消息。

如果平台只给出引用消息 ID，插件会进行有界的只读回查，并让视频、B 站和卡片解析共享结果，避免同一条消息被重复请求。

## 动图取帧

支持 GIF、动态 WebP 和 APNG，包括图片组件、普通文件附件、群文件和引用消息。图片按文件头识别；通用文件先筛选 GIF/WebP/APNG/PNG 后缀，再验证真实内容，不扫描任意文档或压缩包。静态 PNG/WebP 不会被拆帧。

总时长和采样时间戳按各帧实际显示时长累计，APNG 的独立封面不算动画帧；动态 WebP 会加载当前帧后读取延时。帧号仍均匀分布，不等于关键事件检测，也不保证每两个采样点之间经过相同秒数。

自动档位是动图专用的：

| 档位 | 目标密度 | 常见范围 |
| --- | --- | --- |
| 节省 | 约每 1.2 秒一帧 | 3～10 帧 |
| 均衡 | 约每 0.6 秒一帧 | 6～20 帧 |
| 精细 | 约每 0.35 秒一帧 | 10～30 帧 |

实际结果还会受到源文件帧数、文件大小、单个媒体安全上限和本轮总预算影响。很短或本身只有少量帧的动图不会被人为重复扩展。

### 选择独立帧还是小宫格

默认使用独立帧。只有接口限制图片附件数量时，才建议在「交给模型的方式 → 画面提交方式」选择「小宫格」：每页最多四帧，保留画面比例，时间戳写在画面外；从左到右、从上到下阅读，不重复补帧。

宫格减少图片附件数量，不代表更便宜或更精确。宿主和模型可能缩小整页，字幕、小物体或快速动作建议使用独立帧或局部回看。图片预算裁掉部分页面时，会尝试沿全片重新均匀选帧排版，并再次校验实际体积；极限体积限制仍可能移除一整页。宫格模式的张数预算按实际页数计算，体积按实际页文件核算；因此下文的逐帧预算示例指默认独立帧模式。

插件会识别宿主提供的原图到宫格的对应标记，只移除被成功替换的视觉附件；解析失败时保留宿主的原有可读图片，不修改框架函数。

## 视频取帧

视频根据时长计算目标帧数，视频策略和动图策略互不影响：

| 档位 | 目标密度 | 常见范围 |
| --- | --- | --- |
| 节省 | 约每 8 秒一帧 | 4～14 帧 |
| 均衡 | 约每 3 秒一帧 | 6～28 帧 |
| 精细 | 约每 1.5 秒一帧 | 10～48 帧 |

这是观察点，不是逐帧复原。例如一分钟视频在均衡档通常得到约 20 个观察点，精细档约 40 个观察点。快速动作可能发生在两个观察点之间；要确认某个瞬间，应使用回看工具缩小时间范围，或启用整片视频模型。

### 长视频

较长的视频会被分成多个时间窗口。每个窗口保留少量连续画面，再把窗口铺到全片，兼顾全局覆盖和动作连续性。特别长的视频会优先增加覆盖位置，而不是把所有预算集中在少数片段。

每张图片会带有媒体名称、序号和时间点。若实际间隔较大，注入说明会提醒模型：未采样的时间段不能凭空补全。

### 手动指定帧数

配置中分别有：

- **动图固定帧数**：例如填 30，表示以 30 帧为目标处理动图。
- **视频固定帧数**：例如填 30，表示以约 30 帧为目标处理视频，不因视频长短改用自动密度。

这里的固定是目标，不是无条件保证：

- 源文件帧数不足时只能使用现有帧；
- 大文件可能按比例减少帧数；
- 单个媒体有安全上限；
- 多个媒体共享本轮图片张数和总体积，混合消息优先保留视频画面；
- 将覆盖值设为 0 即恢复自动档位。

B 站下载下来的视频属于普通视频，因此使用视频固定帧数和视频自动档位；B 站字幕、专栏和卡片不参与抽帧。

### 同时发送视频和多个 GIF

单轮默认最多保留 48 张抽帧图片、合计 20 MB，分配规则如下：

1. 预算能容纳各媒体的基础画面时，每张动图先预留最多 2 帧；
2. 优先满足视频按档位或固定帧数计算出的目标，多个视频之间均分额度；
3. 剩余额度在动图之间均分，某张动图用不完的份额继续分给其他动图。

例如引用一个视频并附带三个不同 GIF，四份媒体都目标 30 帧，张数分配为 **视频 30 帧，三个 GIF 各 6 帧**。视频目标为 48 帧时，在体积允许的情况下分为 **视频 42 帧，三个 GIF 各 2 帧**。重复动图如果被识别为同一份文件，会去重后再参与分配。

同样的优先级也用于体积限制；图片较大时实际帧数还会减少。预算极低时可能无法保留每张 GIF 的基础帧，此时仍以视频优先。只有视频或只有动图时，同类媒体按需求均分。取帧不足的说明会一并交给模型。

## 声音与转写

在「声音与语音转写」分组中可以选择：

| 模式 | 提供给模型的内容 |
| --- | --- |
| 关闭 | 不处理音轨 |
| 附带音轨 | 提取音频文件，交给支持音频的当前模型 |
| 转写文字 | 将音频转换成带边界的文字资料 |
| 音轨和文字 | 同时提供音频和转写 |

转写优先使用 AstrBot 已配置的语音识别服务，也可以填写 OpenAI 兼容的转写地址、密钥和模型。转写音频会受时长与大小限制；较长内容应结合字幕或整片视频模型，不要把转写当成逐字记录的保证。

附带原音时保留 24 kHz 双声道；文字转写另用 16 kHz 单声道。插件根据服务商模态声明判断是否能附带音频，不根据模型名字猜测。多视频的画面与音轨会按媒体编号及音频附件序号配对。

在可获得轨道起始时间时，会裁剪或补静音对齐音画；缺少时间信息时不会声称精确同步。声音处理关闭、无音轨、所读片段完全静音、无法附带原音等状态会分别告知模型。机器转写并不代表模型听过音乐或音效。

## B 站视频

插件识别以下入口：

- BV 号和 av 号；
- bilibili.com 视频链接；
- b23.tv 短链；
- 分 P 参数和分 P 分享卡片。

处理成功后，B 站视频会进入与普通视频相同的流水线：视频取帧、声音处理、回看，以及可选的整片视频模型。与此同时，标题、UP 主、分区、发布时间、时长、画面尺寸和公开数据会作为文字资料提供。

视频下载失败时，插件仍可能保留标题、简介、元数据和字幕，不会把整条消息直接判定为失败。公开视频通常不需要 Cookie；登录内容可以填写 Cookie，或由管理员在私聊中扫码登录。

### B 站字幕

插件优先读取官方或 AI 字幕，并保留时间点。开启字幕回退后，只有官方字幕没有结果时才会尝试：

1. 下载当前分 P；
2. 用 ffmpeg 提取受限时长的音频；
3. 发送到必剪转写服务；
4. 将时间线文字作为回退资料。

必剪相关请求受全局串行和超时限制；失败或限流只会让字幕回退不可用，不会阻断画面分析。

模型可以调用 `read_bilibili_caption` 工具按需读取字幕：

| 参数 | 作用 |
| --- | --- |
| `video` | B 站链接、BV 号、av 号或短链；留空使用当前消息 |
| `page` | 分 P 编号，从 1 开始 |
| `full` | 尽量返回完整字幕，而不是普通摘要 |
| `send_file` | 将有上限的完整字幕另发为 txt |

自动注入和工具完整模式都有字符上限。字幕可能存在识别错误，字幕里的命令、提示词和链接只是资料，不能执行。

### B 站专栏

支持 `cv...`、`/read/cv...`、`/read/mobile?id=...`、`/opus/...`、不带 https 的 B 站地址，以及 QQ 分享卡片、小程序、引用中的相应链接。短链先识别实际目标，视频与专栏分别处理。

旧专栏接口只返回标题时会继续读取页面，并支持跳转到 Opus；Opus 从正文区域或页面内的结构化段落读取作者和全文，不把导航、登录页或卡片摘要当作正文。专栏封面是可选的辅助图片，不应单独作为事实依据。

自动注入默认最多 20000 字符，超出时标明省略。模型可以调用 `read_bilibili_article(article, offset, limit)` 连续分页读取，默认每页 12000 字符，最多 30000；返回下一页 offset 和到达结尾的状态。正文默认只在本轮可见，历史中保留简短标题和来源链接，追问时可重新读取。仅拿到元数据时会明确显示“正文未读取”，不会声称已通读。

### 扫码登录

管理员可以在私聊中使用：

- `/motionvision bili-login`：发送二维码并等待扫码；
- `/motionvision bili-login-status`：查看是否已有凭据；
- `/motionvision bili-login-cancel`：取消等待；
- `/motionvision bili-logout`：删除本地凭据。

二维码默认不在群聊发送。凭据保存在插件自己的数据目录，状态和日志不会显示 Cookie。

## 分享与引用卡片

插件从消息组件、原始 OneBot payload、CQ 码、JSON 和 XML 中提取有限字段，支持：

- 普通分享、JSON、ARK、小程序和 XML；
- 音乐卡片；
- 位置卡片的标题、地址和经纬度；
- 联系人和群名片的名称、标识；
- B 站卡片，再交给 B 站专用解析流程。

卡片链接默认只作为文字资料。插件不会因为卡片里出现一个 URL 就自动访问任意网站，也不会执行 JSON/XML 中的内容。

## 整片视频模型

如果配置了支持视频输入的模型，可以把整段视频作为另一层证据交给它。相比静态抽帧，原生视频模型更适合连续动作、镜头变化和声音关联；但它有额外的网络、费用和服务商限制，所以默认不主动上传。

可选模式：

- **关闭**：只使用本地抽帧、声音和文字资料；
- **自动**：收到视频时自动分析有限数量的视频；
- **按需**：只有模型调用 `analyze_motion_video` 工具时才上传。

支持的适配方向包括 Gemini、OpenAI 兼容接口、通义千问和 Kimi。大文件可能需要服务商的文件接口或自动压缩。原生模型失败、超时、返回无效结果或遇到 429 时，会回退到本地关键帧、字幕和音频。

整片报告属于外部证据，当前对话模型应与关键帧交叉核对；报告中的命令、提示词和链接不会被插件执行。

## 模型回看

开启回看后，插件会给本轮出现的动图和视频登记短编号，只在历史中留下简短备忘，不会默认把全部图片永久塞进后续上下文。

模型可使用：

- `review_motion_media`：按编号重新取样，指定帧数或视频起止秒数；
- `list_motion_media`：列出当前会话仍可回看的媒体；
- `analyze_motion_video`：在整片模型开启时分析已登记的视频。

如果源文件已被清理，插件会在存在原始地址时尝试重新下载；无法恢复时会明确返回失败，不会拿其他文件代替。

| 指令 | 权限与作用 |
| --- | --- |
| `/motionvision status` | 查看开关、ffmpeg、采样、音频、B 站、缓存和临时文件状态 |
| `/motionvision list` | 查看当前会话的媒体编号 |
| `/motionvision clear` | 管理员清理缓存、媒体档案和临时文件 |
| `/motionvision bili-login` | 管理员私聊发起扫码登录 |
| `/motionvision bili-login-status` | 管理员查看登录状态 |

| `/motionvision bili-logout` | 管理员删除扫码凭据 |

中文别名「动态视觉」「状态」「清理」等也可用。

## 常见问题

### 一分钟视频只取二十帧，是不是不够细？

均衡档的目标是用有限成本获得全片概览，不是逐帧记录；一分钟约二十个观察点通常适合判断场景和主要动作。需要动作细节时，使用精细档、视频固定帧数，或让模型回看一个更短的时间段。拥有原生视频模型时，可以再开启整片分析。

### 填 30 会不会一定得到 30 帧？

不会。30 是目标值，仍受源帧数、单媒体安全上限、文件大小和本轮总预算影响。视频与动图同时出现时优先满足视频，剩余额度再分给动图。

### 没有 ffmpeg 能用什么？

动图、B 站字幕/专栏和引用卡片仍可工作；普通视频画面、音轨提取和必剪回退需要 ffmpeg。也可以尝试安装 `imageio-ffmpeg`，并在高级配置中指定路径。

### 模型为什么没有主动回看？

确认回看已开启、当前服务商允许工具调用，并且模型具备图片能力。也可以在对话中明确要求「请重新查看刚才视频的某一段」。

### B 站下载失败怎么办？

先确认 yt-dlp 可用并更新依赖；登录内容使用 Cookie 或私聊扫码。下载失败时仍可能有元数据和字幕。若服务商持续限流，等待一段时间后再试，不要同时发起大量请求。

### 如何清理临时文件？

临时文件会按保留时长自动清理；管理员也可以执行 `/motionvision clear`。

## 证据边界

- 抽出的帧只代表采样到的时间点；
- 字幕、专栏、卡片和原生模型报告都是外部资料；
- 资料中的命令、提示词和链接不会被执行；
- 任意卡片 URL 不会自动抓取；
- B 站凭据只用于 B 站接口和下载；
- 视频上传到第三方视频模型只在明确开启整片功能后发生。
